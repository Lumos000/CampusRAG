# 五类主题与学院资料的独立补采

新增配置 `config/sites_topics.json`，保留原配置 `config/sites.json`。
站点范围限定为校主站、本科生院、本科招生办公室、学生工作部（处）、图书馆、财务处，以及四个学院的探索入口。v3 最终入库仅保留计算机学院和人工智能学院，具体排除规则见 [v3 构建说明](college_database.md)。
学院入口根据学校公开的[教学机构目录](https://www.njupt.edu.cn/jxjg/list.htm)及各学院导航于 2026-10-29 核验：

- 通信与信息工程学院：`scie.njupt.edu.cn`。
- 计算机学院、软件学院、网络空间安全学院：`cs.njupt.edu.cn`。
- 人工智能学院：`ai.njupt.edu.cn`，采用独立官网资料。
- 自动化学院：`coa.njupt.edu.cn`。采用当前首页链接的 `2206/list.htm`，避免将旧网站栏目 `2203/list.htm` 当作当前简介。

## 运行

```powershell
conda activate rag
python scripts/collect_topics.py --max-pages 120 --max-depth 2
```

默认新建 `data/collections/topics_UTC时间戳/`，也可以用 `--output` 指定一个不存在的新目录。目标已存在时立即停止，防止覆盖已有结果。
本命令不会打开、导入或修改任何数据库，不更改应用配置及现有索引。

原 `data/raw/manifest.jsonl` 及其文件只读复用，新下载内容写入新目录的 `raw/`。合并清单、清洗结果和覆盖报告均写入新目录。复用资料引用原始文件路径，因此不要删除原始文件。
同一 URL 以新采集状态为准；新采集失败时不会用旧快照冒充本轮成功。

只读复核已有原始资料，不联网：

```powershell
python scripts/collect_topics.py --skip-crawl
```

## 筛选与验收

- `allowed_domains` 限定站点，`follow_keywords` 限定新发现链接的标题关键词；附件必须命中标签或父页主题，分页保留跟踪。已有配置不设置该字段时保持原行为。
- 新流程清洗仅接收配置中的明确部门站点及主题标题；无主题命中的记录进入 `topic_scope_check` 待复核，不直接删除。原清洗入口的默认行为保持兼容。
- `clean/clean_decisions.jsonl` 保留接受、排除、重复和待复核的理由。
- 研究生、博士、硕士、继续教育、成人教育、自考等标题进入范围待复核；同时明确包含“本科”的混合标题仍按主题检查。
- `coverage_report.json` 按五类主题及每个学院的简介、本科培养、学生服务列出有效去重正文数、待复核候选数和最多三个来源示例。重复正文的学院来源别名也参与统计。
- 图片承载的专业介绍标记为 `image_content_requires_ocr` 待复核，不会因有页面标题就算作正文覆盖；宣讲会等活动标题也进入待复核。
- 标题命中只代表存在候选依据，不表示正文完整、政策仍有效或主题覆盖完整。报告中 `missing` 是下一轮补采或解析改进的明确缺口；栏目首页、附件容器页及未接受正文不会充当覆盖证据。
- 日期未知保持空值并统计；核实适用学年、政策修订、旧版本及临时开放通知后再用于回答。此次不自动推断政策失效时间。

后续应优先检查报告中的缺口和核心主题待复核项，再扩大采集。扫描件 OCR、旧 Office 转换及人工复核结果回填尚未自动实现。
验收后的数据库导入和索引构建需另行指定新路径；本补采命令只生成可检查的文件，不执行入库或切换。
