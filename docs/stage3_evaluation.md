# 阶段 3：执行范围与问题约束

本阶段保留阶段 2 的架构和数据结构，修改 `database/query.py`、`database/normalization.py`、`rag/planner.py`、`rag/numeric.py` 和 `rag/service.py`。

分类字段的 `in` 允许每个对象匹配多条记录，聚合读取 SQLite 完整匹配集合；`lookup` 仍要求唯一值。执行后核对问题中真实列举对象的记录覆盖及额外记录，按真实字段名称辅助区分同名对象，字段不明确时拒答。非法字段反馈包含所选表格的合法字段、角色和单位。数值阈值必须来自原问句，且比较关系不能改变。

正文 Facts 的条款、明确排除条款、上下限和个人实际值分开校验。示例不能代替个人参数，界限不能直接充当实际发生值。每周、每月等周期用量不能直接相减；通过问题给定的周期数完成乘法后，可与问句要求的总范围比较。周期单位不能猜测换算。对已核验的界限计算，程序标注“按下限标准计算”“按上限标准计算”或“按所引界限计算”，不声称任意界限相减后仍是数学上下界。

无合适表格度量的正文计算只提供 Facts，复用原有较短的规划提示，只允许真实 fact_id 和问题常数，拒绝模型切换到未提供的表格字段。示例最多使用常见五步周期计算结构，依然从实际证据和问句构造，不包含学校专用数据、测试答案或固定数据库 ID。计数比例示例的两步计数绑定真实字段，分母仍由 Python 从全表计数。仍共享最多一次规划修复预算。

执行器核对原始单元格与规范化数值、单位及年份元数据是否一致。实际年份字段缺失时，不把未知年份记录当作确定范围。多级表头只用叶级字段判断年份，避免表格标题中的学年污染课程名等字段。`scripts/refresh_table_metadata.py` 在原数据库副本上保留备份，事务更新派生元数据；原始表、列、行、单元格及正文分块哈希前后一致，完整性和外键检查通过。索引未重建，审计见 `data/eval/stage3_normalization_audit.json`。备份位于忽略目录 `.tmp/`，不随 Git 分发。

诊断新增 `execution_completed`、`question_constraints_ok` 和 `question_validation` 错误阶段；`semantic_correct` 仍为 null，由逐题评审决定。模型没有参与最终 Decimal 运算或答案改写。

初次原型虽然通过 108 项自动测试和 12/12 开发回归，36 题仍暴露两处回归：新正文提示诱发逐条 lookup 并混入其他条款；过于保守的同名对象消歧拒绝了原本正确的分类计数。没有把这次运行作为阶段验收，也没有进入阶段 4。实际错误规划保存在 `data/eval/stage3_precheck_failures.json`，完整原型运行另存 `.tmp/stage3_precheck/`。

随后恢复复用原有短提示；当问句中的字段类型直接紧邻真实对象值时，优先对应字段，不能因为另一列也含同名值就拒绝。新增主项目/子项目同名但记录范围不同的测试，正确绑定可计数，错误字段应拒绝并反馈 Schema。自动测试现为 109 项全部通过，另包含不同结构的分类多行聚合与唯一 lookup、分类比例完整范围、叶级年份、缺失年份、原始数值篡改、Schema 反馈、五步周期运算及条款/实际值边界测试。

最终真实模型回归 12/12。36 题完整复跑无运行异常、无联网调用；严格语义正确 24/36（66.67%），阶段 2 为 22/36，原始基线为 19/36。数值题 5/8（62.5%），阶段 2 为 3/8，基线为 1/8。C02 的周期计算与 C07 的分类多行计数新增正确；C04、C06 的原型回归均已修复。原本正确的题目没有新增错误或错误拒答。28 题与原始答案、引用和计算对象完全一致，复用原评审；C06/R04 与阶段 2 完全一致，复用已审记录，其余 6 题重新逐项核对。

普通文字题（fact、procedure、list）11/20，时效题 4/4；本阶段未修改普通生成路径。应拒答题 4/4，另有 3/32 可回答题被错误拒答。引用支持率 41/91（45.05%），完整来源覆盖 22/32（68.75%）。引用支持率低仍主要来自普通回答携带全部检索引用，不能用数值题的改善代替文字和引用质量的改善。

8 道数值题中，首次规划语法合法 3/8，经过最多一次修复后语法合法 6/8，全部步骤执行完成 6/8，执行及问题约束通过 5/8，人工语义复核正确 5/8。这些是分别统计的状态。C03 完成两次 lookup 和减法后得到负差额，问题约束拒绝了该结果；不能把它算成正确答案。完整逐题对照见 [stage3_case_comparison.md](stage3_case_comparison.md)，运行、评审和错误阶段统计位于 `data/eval/stages/stage3/`。

剩余三道数值题：C01 缺少问题常数的 lookup；C03 首次缺少操作数，修复后颠倒比较对象；C08 缺少全表分母的 count。它们的证据均已检索到，失败集中在小模型的操作数完整性和主体绑定，而非 Decimal 运算。全部 12 个严格未通过项的主因分布为 generation 8、annotation_boundary 1、plan_validation 2、question_validation 1；其中 F02 的金标边界保持原样并单独注明，没有为提升分数修改金标。

阶段 0～3 的优先改动与验证已完成，但数值规划尚不稳定，不能声称已达到泛化验收。因此按“数值题稳定后再处理文字回答”的顺序，阶段 4 和独立 v2 的最终评测尚未执行。下一步优先压缩规划输入中的重复元数据，清楚区分 fact_id 与步骤 id，针对缺失操作数和主体顺序做一次修复；继续保留完整证据和当前拒答边界，并以新的完整一轮评测验收。随后再整理运行时条款与实际支持引用，必要时才重新分块建索引，最后一次使用预先冻结的 v2 检验泛化。上述 24/36 是开发诊断成绩，同一助手评分且只有一次最终完整运行，不能当作独立泛化准确率或稳定性保证。
