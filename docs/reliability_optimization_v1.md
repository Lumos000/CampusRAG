## 独立复现与修改

先新增合成表和直接计划测试，再修执行器。基线组件从 Git 提交重放，复现记录见 `data/eval/reliability_reproductions.json`；这是执行器测试，不是模型准确率。

- 分类与数值阈值复合筛选：原检查把整个类别当作必须覆盖的范围。现在从原问句中重新绑定明确阈值，校验限定范围内的完整记录集合，不能靠模型遗漏筛选来扩大范围。漏选、额外记录、链式 filter 均有正反例。
- 计数、求和与平均混淆：记录内部运算量种；计数可以由合法、不重叠的计数相加产生，不能把金额求和当记录数。区分平均与合计，并允许同范围 sum/count 的平均计算，保留所有单位、年份及原始数据校验。
- 排除方向反转：加入受限 `not_in`，仅在原问句明确排除对应真实对象时允许；反向 eq/in 及无排除依据的 not_in 均拒绝。没有引入自然语言约束框架。
- 比例分母：另行复现“局部计数冒充全表分母”能通过的问题，检查明确全表口径下的完整明细或唯一合计行。缺失分母步骤仍必须由模型修复，不由程序猜测补齐。
- 多级表头：从叶级向上查找明确单位，上级版本括号不再遮住“面积（平方米）”。当前已有数值列未发现需要因此刷新的单位记录。

尝试过规划 Facts 筛选、主体排序、元数据压缩和更明确的补步骤提示，但完整候选运行的数值题仍为 5/8，没有显示收益，已撤回这些改动，保留原 Facts 和规划提示。`rag/numeric.py` 最终没有功能改动；规划器只增加受限 `not_in` 的语法支持。最多一次修复，程序不生成缺失操作数或数据，新增的计数、平均及分母执行约束继续保留。

文字部分运行时整理现有检索条款，优先同资料相关段落；只在指定条款明显位于 chunk 末尾时补读同文档相邻块并记录实际块 ID，不重建分块或索引。模型摘录原句并返回本次候选编号 E1/E2 等，程序将编号映射到真实 evidence_id，核对所引原文中能否定位完整原句，再生成引用。不能将“不允许……”中的“允许……”作为合法子串摘录。未知编号、不合格式或无法定位的改写，回退相关原文摘录，不再次调用模型，也不附上全部检索来源。编号与摘录定位校验不等于完整语义支持，诊断的 `support_verified` 保持 null，实际支持率由逐题评审决定。

原文回退曾导致个人实时课表请求被公开排课制度代替，已用通用个人成绩、借阅记录及查询流程正反例复现并修复：本系统只使用公开资料，明确索取个人记录时拒绝，询问如何办理、查询流程时仍可正常使用公开指南。该边界只处理已确认的回归，没有新增个人数据接入或复杂查询分类器。

实际修改：`database/query.py`、`database/normalization.py`、`rag/planner.py`、`rag/service.py`、`rag/citations.py`；新增 `tests/test_reliability.py`。没有更换模型、检索算法、数据库结构或引入训练、Agent 框架。
