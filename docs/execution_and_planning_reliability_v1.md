# 执行漏洞、修复输入及正文预算规划验证

本轮以 `3ce4b7f` 为基线，按顺序独立验证三个阶段。最终保留执行器安全校验和正文预算示例，撤回修复输入候选。模型、检索、SQLite、Decimal及三列CSV接口不变，无新依赖、训练、数据库或索引重建。

## 第一阶段：两个执行漏洞

修改 `database/query.py`，新增 `tests/test_operand_scope_guards.py`。

- 原执行器接受“4×89+6×137=1178元”的交叉费率计划，而正确配对为“4×137+6×89=1082元”。现在在中间乘法检查正文人数和费率的主体、政策及明确分组，不能只靠最终证据集合覆盖来认定正确。
- 原来源检查只作用于fact_id，单一错误候选表也可能回答用户指定的另一份办法。现在真实表格明细也参与来源校验，复用现有标题/表名信息；没有资料归属依据时，不因table_id合法就放行。
- 保留用户给定人数、明确借用另一组标准、正文统一标准等正例。未放宽年份、单位、对象或范围校验。

新增测试先复现4项失败，修复后第一阶段全部227项测试通过。完整单次回归：12/12，任务书4/4，开发36题33/36，已公开v2为13/16，旧校园题6/10；答案和引用全部不变。收益是堵住已复现的错误放行，不宣称答题数量增加。

记录：`data/eval/execution_guards_v1/`，包括源码快照、失败测试、完整首次/修复规划、逐题结果及 `acceptance.json`。

## 第二阶段：一次修复输入试验，撤回

仅修改失败计划原始字符串的表示：不再用json.dumps二次编码；首次提示、修复目标和最多一次修复不变。新增3项输入契约测试，全部230项自动测试通过。

完整回归仍有12/12及任务书4/4，但开发36题33→32，旧校园题6→5，已公开v2保持13/16。原正确的C04和L3N04在修复时重复未闭合JSON，变为拒答，无新增正确题。C03、V2C06、V2C08、L3N03仅改变失败形态。

因此撤回该行代码及3项候选测试，不在本轮继续调整该方案。原始源码、候选测试和完整负面结果保留在 `data/eval/repair_input_v1/`。表示更简洁不等于修复更有效。

## 第三阶段：保留全部证据，只修正受误导的预算示例

修改 `rag/planner.py` 的现有step_example，新增 `_body_budget_example()`，不增加Planner或新调用。

仅对明确指定一份办法、询问名额/人数与每人标准的总预算，且其正文存在完整确定的人数/费率配对、候选表格没有可确认的指定办法归属时，给出正文计划示例。按真实主体、来源和分组匹配，先分别相乘再求和，覆盖一至两类、最多7步。用户给定人数只有与唯一正文名额一致时才作为该示例中的literal；其他复杂情况沿用原逻辑。

全部检索结果、Schema和Facts继续提供给Qwen；不删候选、不新增source_match标签、不执行示例代替模型。最终仍由Qwen输出计划，SQLite/Decimal验证执行。字段、fact_id、常数和来源均来自当前证据及问题，不包含校园题答案或固定数据库ID。

新增7项合成测试覆盖单/双人群、问题常数、保留全部模型证据、缺费率、人数不一致以及直接表格合计。最终全部236项自动测试通过。

## 逐题变化与支持核验

- **L3N02新增正确**：同一指定办法的研究生4×12000、本科生6×8000，合计96000元。四个数值、主体和单位均见原文；模型实际生成7步计划，通过中间配对和最终来源校验。
- **L3N05新增正确**：同一指定办法的本科生3×5000、研究生9×8000，合计87000元。全角费率原文可定位，实际7步计划无跨来源混用。
- **L3N06仍失败**：模型保留19人常数，却仍选另一资料的2000元/人，被来源校验拒绝，没有输出错误的38000元。未把示例的正确计划或执行成功冒充系统答对。
- 原正确题无回归，文字答案未变化。开发36题、已公开v2的首次规划提示逐字不变；旧校园题仅上述3题的首次提示改变，已逐题核对。

文档级引用支持数：开发36题29/29、已公开v2为11/11保持；旧校园题5/5到7/7，分母增加来自两道新增正确答案各引用一份实际办法。无引用拒答不进入该分母，不能据此宣称全部问题可靠。

最终完整同题对照见 `data/eval/body_budget_v1/same_question_comparison.csv`；操作数和记录审查见 `all_numeric_operand_audit.json`。完整首次/修复提示、执行轨迹、引用及人工判定均独立保存。
