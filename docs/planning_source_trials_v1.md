# 规划输入来源约束：两个候选均撤回

本阶段以已通过回归的 `fact_scope_v1` 为基线，完整保留两次单次评测和金标。基础模型、检索、数据库、索引、JSON计划机制及最多一次修复均未更换。另独立修复已复现的人均标准差额单位误拒，保留元/人，不将费率转换成总额。

## 直接删减候选

`planning_scope_v1` 在明确指定的来源均能由真实文档标题确认时，只向模型提供匹配来源的Schema和Facts。未识别的来源、多来源缺失及仅能定位汇编章节时不猜归属。

220项自动测试、12/12回归和任务书4/4通过；但已公开v2的V2C01、V2C04、V2C05从正确变成拒答：分别产生非法lookup参数、遗漏奖励对象、遗漏用户人数步骤。即使删掉的是无关候选，也不能把更短上下文当成收益。该方案撤回。

## 保留候选并标记来源

`planning_scope_v2` 保留全部候选、真实ID和元数据，增加source_match标记；示例及执行可用表格只使用匹配来源，未触发来源识别的问题保持原提示。没有新增Planner或模型调用。

222项自动测试、12/12回归和任务书4/4通过；但V2C05仍从正确变为缺少人数步骤的拒答。它没有达到原正确题不退步的要求，因此同样撤回，不按题号或学校名称设置启用开关。

两次输入改变均带来规划回归；这不证明所有来源约束都无效，也不证明其内部原因一定是注意力或遗忘。这里只否定这两个具体候选。结果表明，当前0.6B模型对输入变化敏感，必须用最终语义与原正确题集合验收，不能只看来源更干净、JSON合法或执行成功。

## 独立保留的人均单位修复

阶段一原始模型计划已经正确选择同一政策的12000元/人与8000元/人并相减，却被“多少元”目标单位检查误拒。直接重放原计划确认该误拒；合成人群137元/人与89元/人的正反例证明修复不依赖校园答案。

明确询问人均标准差额、且不存在总额或预算要求时，允许结果保留元/人；总额、预算差额不允许以费率差代替，不放宽其他操作数与来源校验。原金标单位和自动精确单位匹配函数均不修改：按上下文正确的人均答案与字面单位匹配分开报告。

恢复后运行时只保留Facts绑定和该单位修复；service.py与planner.py恢复为阶段一原代码，无source_match等实验逻辑。正式测试为213项：原199项、10项Facts绑定测试、4项单位测试。两个输入候选新增的9项接口/示例测试随各自源码封存，不冒充正式保留功能，也未删除已有缺陷回归。

当前基础模型完整回归：12/12、任务书4/4、开发36题33/36、已公开v2为13/16，均无原正确题退步。旧校园10题的人工语义评分为6/10、数值2/6；其中4000元/人符合原问题的人均标准差，但原金标单位简写为元，自动数值单位精确匹配仍为1/6。原金标未改，不能把两个评分口径混用。

所有新评分来自完整单次运行，没有拼接两候选的最好答案。新封存测试未运行。候选源码、候选测试、失败输出、逐题复核分别在 `data/eval/planning_scope_v1/`、`data/eval/planning_scope_v2/`；最终保留版本在 `data/eval/fact_units_v1/`。
