# 正文费率抽取修复 v1

本次只在 `NumericEngine.text_facts()` 修复两个已复现的问题，不训练或启用 LoRA，不修改生产数据库、索引或检索算法。

## 根因与改动

1. 金额分母正则仅识别半角 `/`。在匹配副本中将全角 `／` 一对一替换为 `/`，原文不变，偏移映射不变。规范单位保留为 `元/人` 等，`quote`、`span` 和 `raw_value` 保留原文的斜杠、空格及完整复合单位。
2. `技术组：3人，37元/人` 的金额前没有关系词或主体，原流程跳过。现在仅当金额紧接同一证据内已识别的确定人数、间隔只有逗号、且明确带 `/人` 时，继承该人数的主体。单价使用独立的“人均标准”字段，避免人数和费率被当作冲突值；引文覆盖人数主体至费率，均能定位原文。

不跨证据、句号或分号继承；不为缺主体、人数范围、近似值、缺分母等情况补猜。对单价后跟“左右”或另一金额的模糊表达保守跳过。重复人数仍更新相邻位置，因此两条不同单价的真实冲突会被原冲突检查剔除，而不是只保留第一条。

## 验证

新增 `tests/test_text_rate_extraction.py`，23 项测试覆盖全/半角斜杠、三种分母、PDF换行、不同主体、原文偏移、缺失和不确定条件、冲突及完整执行。先保存失败日志，再修改实现；初始 11 项失败，边界补测另复现 2 项失败，修复后全部通过。

独立构造 `技术组：3人，37元／人；研习组：7人，53元/人`，抽取四条事实后直接提交受限计划，Decimal 得到 `3×37+7×53=482元`，全部操作数均有真实证据。测试不依赖模型或校园数据答案。

|完整基础模型回归|修改前|修改后|
|---|---:|---:|
|自动测试|176通过|199通过|
|12题开发回归|12/12|12/12|
|任务书四例（包含在12题内）|4/4|4/4|
|开发36题|33/36|33/36|
|其中数值题|5/8|5/8|

|其中数值题|5/8|5/8|

36题及已公开v2的答案和引用逐项不变。旧校园题仅 L3N01 的拒答原因变化：模型选择另一办法的事实，被来源校验拦截，仍未答对。没有新增错误答案、错误拒答或引用，文档级引用支持数保持29/29、11/11、3/3；这些比例不包含无引用的拒答，不能代表所有问题均正确。

全部评测为各自单次完整运行，网络尝试数为0，三列CSV格式验证通过。新封存校园题和合成测试未运行，旧金标、历史输出和LoRA实验记录未覆盖。这些仍是开发回归结果，不是新的独立泛化准确率。

## 结论与范围

保留该最小修复：确定性抽取缺陷得到消除，既有正确功能未退步。但本次没有最终答题正确率收益；规划器仍可能选错来源、遗漏常数或生成非法步骤，新增费率也可能受现有上下文截取影响。这里只支持明确紧邻的“人数，单价/人”格式，不声称已经解决全部省略表达、跨行主体或复杂政策层级。
