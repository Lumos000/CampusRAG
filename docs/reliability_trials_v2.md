# 小范围可靠性优化与淘汰记录

基线为 b3711e0。保留通过验收的原文句段选择，撤回无收益的数值约束代码和全部新增运行依赖。没有更换模型、检索系统、SQLite 或 Decimal。

`reliability_trials_v2` 仅是本轮实验记录名称，与封存的 `independent_v2` 测试集无关。

## 实际修改

- `rag/service.py`：模型只返回真实句段编号；程序恢复现有文档块顺序、保留句段原文并生成引用。无效或空编号仍回退已有原文，不增加模型调用。
- 句段整理保留带共同前提的列表、嵌套列表和附属例外。表格对象按问题明确给出的完整字段值匹配；保留全部已检索匹配记录，不按三条截断，部分选择触发保守回退。
- `tests/test_sentence_selection.py`：合成资料覆盖条件、否定、例外、列表、四条以上记录、相似名称排除、未知编号、去重及跨块原文顺序；两个原有正例 Mock 更新为新契约，断言未放宽。
- `scripts/evaluate_reliability_trial.py`：冻结新候选及补丁，复用现有评测器，拒绝覆盖旧候选，不读取独立 v2。外部 AnswerResult 与三列 CSV 不变。
- `planner.py`、`generator.py` 和 `pyproject.toml` 的约束生成试验全部恢复基线字节；没有保留新 Planner、接口或依赖。

LM Format Enforcer 发布版与 Transformers 5.20.2 导入不兼容，改用官方固定提交 `817f944fcc8851917c40300a47f62d1defc3ffc3` 的兼容修复试验；没有升级 Transformers。
约束候选145项自动测试通过，但数值语义结果仅 4/8，完整36题降为32/36，C05新增误拒答。JSON格式约束不能验证步骤先后依赖、补出问题常数或确定比较方向。模型为满足步数追加无用求和，也不能解决缺失操作数。

常数来源、减法方向及完整分母继续由原有数值正反例和12题回归覆盖。本轮新增的6项约束原型测试随失败补丁归档，撤回原型时一并移出运行测试；最终新增14项文字合成测试，未通过删除旧断言来维持成绩。

C01/C02/C08单题观测分别为223.733/209.715/293.272秒；这包含各题检索、生成及首次约束开销，且未控制其他运行负载，不能作为通用性能基准。它足以说明本地此配置未展示可接受收益，而不是证明该库在所有模型或后端均无效。
失败候选完整JSON、计划、修复、字段绑定及执行诊断均保留；原型代码与测试在其 `candidate.patch` 中，可从基线重放。最终无该库运行依赖。

## 验证边界与剩余问题

- C01仍遗漏常数；C03仍无法稳定生成正确的比较对象顺序；C08仍遗漏完整分母。维持拒答，程序不猜补操作数。
- 普通文字仍会选择过多真实片段。F04含毕业后救济/运动员例外，P04含首次与变更材料，P05含应征与退役流程；这些旧有情形混用风险未彻底消除。
- 文档级29/29表示每条实际引用文档支持核心事实，不能等同于每句都精准相关。精确原文定位检查只验证来源，不充当语义支持率。最终另存人工回答范围审查；分母与判据均单列，不改原金标。
- 本轮借鉴 [Sentence Window](https://developers.llamaindex.ai/python/examples/node_postprocessor/metadatareplacementdemo/) 的细粒度证据与上下文分离，以及 [ALCE](https://aclanthology.org/2023.emnlp-main.398/) 对正确性、引用质量的区分；没有引入其框架或额外裁判模型。
- 原有短片段长度筛选及缺少明确结构的跨块条件仍有局限，本轮未扩大重构；不能宣称适用于所有条款版式。
- 所有评审由同一助手完成，开发集已参与调试，不是独立或双盲泛化评测。独立v2未读取、未运行，留待用户决定。
- 36个受保护的模型、原始资料、数据库与索引文件哈希与基线一致；不需要重建数据库或索引。正式运行均阻止进程联网，提交CSV保持“问题、答案、参考资料”三列。
- 下一步宜先冻结本候选并安排独立评测；若再改数值规划，应单独验证操作数绑定机制，避免继续堆提示词或用语法成功率冒充答案正确率。
