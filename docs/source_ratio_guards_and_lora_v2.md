# 来源、比例校验与规划 LoRA v2

## 校验修复先于训练

运行时以 `9b40855` 为基础做最小修改，不重建数据库或索引。`numeric.py` 的正文 Facts 增加来源标题及能定位的政策章节；同一汇编内不同办法保持区分，章节标题不再混进主体名称。`query.py` 校验问题明确指定的资料，拒绝混用其他办法的数据，允许用户明确要求的跨资料计算；对“甲占乙”按操作数所对应的实际记录或正文主体检查分子、分母，不以是否超过 100% 判断方向。

数据审查还复现一个相关误拒：表格结果被要求消费其他文档中同名正文 Facts。现将这项正文完整性检查限定于纯正文计算，表格继续使用完整 SQLite 记录的对象、年份、范围、单位检查。`service.py` 只在用户明确指定资料时向模型展示新增来源标签，避免无关问题的提示变化引起退步。

新增 11 个正反例，176 项自动测试全部通过。直接重放历史错误计划：错误的 250% 和跨奖项相加得到 22 人均被拒绝；正确方向 40%、正确来源 12 人均可执行。这是执行器修复，不代表模型已经能自主答对这两题。

修复后完整回归：12/12，任务书四例 4/4，开发 36 题 33/36、数值 5/8，已公开 v2 为 13/16、数值 5/8。后两组答案与引用和基线逐项一致。旧校园 10 题仍为 4/10、数值 0/6；其中原错误 22 人改为拒答，属于减少错误输出，未计为正确率提升。记录在 `data/eval/semantic_guard_v3/`，原始失败和中间修复记录另存，未覆盖。

## v2 数据审查

训练 224 条、验证 42 条、合成测试 42 条，共 14 类计划。学习目标仅为受限 JSON 计划；冻结基础模型，最终计算继续交给 SQLite 和 Decimal。没有把校园评测题、学校金额或最终答案放进训练目标。

针对 v1 证据补齐：

- 命名比例包含小于、等于、大于 100%，问题对象顺序与 Facts 顺序均变化，等值但对象颠倒也不能判对。
- 六列真实 SQLite Schema 随机排列，包含标识、两个可混淆分类/实体字段、年份及两个独立度量字段；字段 ID 是实际持久化 ID。
- 同名主体来自不同办法，也包含同一汇编中的不同政策，以及合法的显式跨资料计算。
- 用户给定常数、已完成数量、上下界、周期乘法后求差、完整表分母和计数比例。
- 资料缺失应拒答；另有带真实执行错误反馈的一次修复样本。

每条标准计划在保存前与独立构造的数值、单位、字段和来源核对，错误修复样本确认原计划确实被拒绝。训练最大序列 1806 tokens，不截断。验证与测试使用新名称、年份、来源和部分不同措辞/结构组合，但共享生成器和运算类别，仍有明显合成分布局限，不能称为真实校园泛化。

## 训练与验收协议

沿用 v1 的 rank=8、alpha=16、学习率 0.0001、微批次 1、梯度累积 8，两轮共 56 次更新，只对 JSON 完成部分及结束符计算损失。首先比较数据改进，不同时更换模型、框架或多项训练配置。仅本地隔离环境安装 PEFT，基础运行环境和基础权重不变。

每轮用验证集执行语义、来源和字段评分。优先选差额、命名比例、完整分母、范围/缺失和修复这五类中最低正确率较高的检查点，再比较总正确数，同分取较早轮次。训练损失低、JSON 合法、执行成功都不能替代答案正确。

检查点选定后先跑全部已公开回归，比较对象是修复后的运行时 `semantic_guard_v3`，不将安全校验的收益归因于 LoRA。要求原正确题不退步、任务书四例和 12 题保持，无新增不支持答案；达到回归门槛后才打开封存测试。新校园题基于原始 PDF/HTML，训练前封存，不用于训练、调整或选择检查点。同一助手命题、样本小等局限必须随结果一起报告。

若 v2 不满足门槛，保存完整输出及原因，适配器不接入默认服务；只能依据验证集和已公开回归中的错误类别设计下一次小范围试验，不能用新封存测试调整训练。后续结果另行记录，不改写本协议或历史金标。
