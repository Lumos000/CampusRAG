# 阶段 2：Schema 与规划示例

Schema 从完整表格内容补充 identifier、category、entity、measure、time 角色，列出问题中真实对象对应的字段及去重后的匹配值。实体缩写必须有相应对象类型支持，不再把“管理学院”的“管理”当成“战略管理”。工时等带单位的时长度量与日期字段分开。完整表格的合计行数量单独提供，生成示例时不再通过三条样例推断是否有合计。

规划示例移除虚构表 7、字段 71/72/73 和甲库/乙库。只有正文 Facts 时使用真实 fact_id；无可用度量的无关表格不再被强行当作算术来源。记录计数使用 count，不对序号求和；仅当问题明确给出阈值时才生成数值筛选。平均学分绩点作为度量名称处理，不因其中的“平均”误选 average。执行端拒绝 sum/average 标识或时间字段。

表格去重继续比较全部行，并加入业务用途和适用对象范围；不通过少量示例判重。明确业务范围时优先提供相符表格，仍保留原 SQLite 数据、原始问题检索与现有索引。

自动测试 103 项通过，包含多列产品表的对象绑定、真实字段示例、无虚构阈值、正文 Facts 示例、完整内容与业务范围去重、时长度量区别于日期、唯一字段归属绑定表格、格式修复预算及固定最终步骤。绩点用无量纲量种标签“绩点”区别于未知单位和任意系数，不改变其数学维度。

真实模型首次诊断出现执行成功但答案错误：C02 直接相减周/月限额、C03 颠倒比较对象、C04 只 lookup 一个门槛；C01 混合引用与常量的 JSON 两次不完整。没有把这些结果计为提升，也未直接进入阶段 3。失败原记录保存在 `data/eval/stage2_precheck_failures.json`（明确标为中止的原型诊断，不是正式阶段成绩）。

为先修复回归，常数改为独立的受限 lookup 步骤，复用原有问题常量与单位校验，算术输入统一展示步骤 ID；旧内联常数仍兼容。每个常数保留问题中的原文位置。另将最低限度的问题检查提前加入本阶段：比较不能只 lookup、方向不能与明确差额语义矛盾、结果单位应符合问句、明确周期数不能遗漏。校验失败仍最多一次修复。完整的分类匹配、对象完整性及条款/适用范围检查留待阶段 3。

后续开发回归曾从 12/12 降到 11/12，再因增加提示退到 9/12；这些不是最终成绩，也没有直接进入阶段 3。固定检索证据的规划探针发现原表格短提示更稳，源信息和运算条件不是越多越好。探针仅用于定位，标为数值/单位匹配，不替代完整检索评测或语义正确率，记录在 `data/eval/stage2_planner_probe.json`。

最终保留较短的表格提示和真实示例，比较对象按问题顺序排序；模型合同固定取最后一步，冗余 output 不再裁掉正确运算，显式 API 选择中间输出仍兼容。只有唯一插入一个闭合括号即可得到合法计划时才允许程序格式修复，不补数据、字段、操作或比较条件；该修复占用唯一修复预算，不能再调用模型修复。原始模型输出不被覆写，诊断区分 initial、repair、syntax_repair，并保存实际提示。

针对新增的个人缺参错误，问题明确声明未给出本人参数时拒绝把公共示例或上下限当实际个人数据；只按公开标准进行假设计算仍可正常使用。

最终真实模型验证：12 题开发回归恢复 12/12；36 题严格语义正确 22/36（61.11%），基线 19/36；数值 3/8，基线 1/8；拒答 4/4，基线 3/4。28 题输出及计算完全不变，其余 8 题重新逐题复核，无新增错误作答。C04 的两个阈值均为第二条，实际引用的 2026 学生手册原 PDF 已复核；C06 在完整表中匹配 10 条记录。C01/C03 仍缺少操作数，C02 周期未转换，C07 分类多行被拒，C08 仍有计划引用错误。全部结果、原始规划、逐题评审和对照位于 `data/eval/stages/stage2/`。v2 未运行。
