# 受限分步数值推理

计算题先用原始问题检索，保留 BM25、BGE、RRF 和 Reranker。检索完成后，模型接收真实表格 Schema 和有原文定位的正文事实，只生成 JSON 计划；SQLite 和 Decimal 执行全部筛选与运算，程序输出答案、算式及引用。普通文字事实题只进行一次回答生成，不预先规划。已核验的数值答案不再交给模型改写。

## 采用的论文思想

- [H-STAR](https://aclanthology.org/2025.naacl-long.445/)：区分文字理解与符号执行，按问题选择路径；本项目保留正文事实、表格与已有领域工具。
- [TabSQLify](https://aclanthology.org/2024.naacl-long.320/)：缩减模型需要理解的相关表格范围；本项目提供候选 Schema 与少量示例行，不生成自由 SQL，也不把示例当成计算全集。
- [QuIeTT](https://arxiv.org/html/2602.20017v1)：问题无关的离线规范化及原始来源保留；本项目使用确定性规则，不调用模型重构表格。
- [TaNOS](https://arxiv.org/html/2604.21495v1)：将运算结构与领域字段分开；本项目只采用简短的运算结构提示，不复现预训练、微调或多模型流程。其预印本强调训练监督的作用，本项目的提示方案不能视为完整复现或等效方法。

## 离线规范化

新增导入的表格自动规范化；原有数据库需执行一次：

```powershell
python scripts/normalize_tables.py
python scripts/check_database.py
```

迁移前自动保存 `campus.before-normalization.db`，存在时不覆盖。迁移只更新派生字段，并增加 `table_metadata`，不删除文档、不改变表格/字段/行/单元格 ID，不改原始表名、表头或 `raw_value`，因此当前索引无须重建。后续若原始正文或表格内容发生改变，仍需重新导入与建索引。

现有 HTML 和 Excel 解析器保留合并单元格展开、多级表头组合逻辑；规范化补充表头单位、确定数值、合计/小计标记、资料年份及年份列的行级元数据。万元/亿元、万人/千人统一为元/人，百分数内部统一为比例。空值、约数、范围和无法识别的格式不填补、不猜测。单位不明确时拒绝聚合。

`table_metadata` 是可重建的派生数据，不替代原始快照。规范化可重复执行。不能从 PDF 或 Word 中可靠恢复的合并关系仍需人工复核，不能把空白单元格自动向下填充。

## JSON 计划

复用 `QueryPlan`，增加 `table_id`、`steps` 和 `output`；复用 `CalculationResult`，增加步骤审计及是否允许修复的标记。单次计划最多8步，常见计算为3至5步。第一版只支持单表计算，保留旧接口供现有调用方兼容。

Schema 包含真实表/字段 ID、原始名称、类型、单位、年份、完整行数与最多3条示例。表格名称明确出现在问题中时优先提供对应表；示例按相关性选择，但执行器始终读取完整 SQLite 表格。

步骤支持：

| 操作 | 输入与行为 |
|---|---|
| lookup | 唯一表格数值，或带原文定位的 fact_id |
| filter | 根据真实字段筛行，后续用 rows 引用 |
| sum / count / average | 对全部匹配明细进行求和、计数、平均 |
| add / subtract / multiply / divide / ratio | inputs 引用前序结果；ratio 输出百分比 |

`filters` 为且关系；`in` 表达多个明确列举对象。支持 `eq/contains/in/gt/gte/lt/lte`。默认排除合计与小计；读取表内总计必须明确 `scope: total` 且唯一确定。表格取值必须使用实际字段 ID，不接受模型提供的行号集合或数值列表。只有问题明确给定的常数可以使用 `literal`，仍需通过原文与单位校验。

模型遗漏 table_id 且只有唯一候选表时可以确定性绑定；遗漏 output 时使用最后一步。若模型误把答案数字写入 output，该数字被丢弃，仍只执行最后一步，不将其作为操作数。步骤内与 id 相同的冗余 output 可以移除。显式 output 引用已有步骤时只保留其依赖路径。这些是格式规范化，不修正数值或推断统计范围。

相同表头和全部原始单元格一致、且年份不冲突的重复表只在模型上下文中合并，优先保留标题中年份明确的来源；数据库中的原表和来源均保留。运算提示和 JSON 示例根据一般运算词、真实字段 ID 与相关示例生成，不含学校数据或答案常量，最终仍以模型提交并通过校验的计划为准。

校验涵盖候选表 ID、字段所属表、年份、筛选对象、唯一匹配、明确列举对象的覆盖、合计行、全部参与值的完整性、单位和分母。不同数值的同结构候选表无法明确范围时拒答。每一步记录实际操作数、结果、算式、字段和单元格位置，引用只来自执行过程实际使用的来源。

格式/字段/筛选计划错误最多共享一次模型修复机会。数据缺失、歧义范围、单位冲突、分母零不触发模型猜测。正文通道只抽取有明确标签和单位的确定数值，并保留原文 span；同名事实存在冲突时不提供给计划。

`config/settings.json` 可设置 `"numeric_shortcuts": false` 关闭现有收费、师资、选科快捷工具。默认保留这些规则，泛化能力由通用执行器承担，而不是新增学校名称或答案常量。

回归集位于 `data/eval/numeric_regression.json`，包括8道人工表格问题和4道校园计算题。人工表格覆盖面积比例、求和、差值、平均、单价乘数量、全表聚合、阈值计数和缺失值拒答。前后都使用真实本地 Qwen3-0.6B、BGE 与 Reranker，原始问题检索；不使用预设模型回答。结果按 Decimal 数值容差及实际引用判分；拒答题要求不产生成功计算和引用，并有计算失败或 verified=false 标记，判分不依赖具体措辞。脚本异常计为错误。

## 当前边界

模型生成合法计划仍可能误解题意，ID和单位校验不能代替完整语义正确性证明。尤其是含糊的时间口径、隐含领域条件、复杂且/或、跨表关联、复杂量纲以及正文中的不规则数值，应拒答或人工明确后再扩展。不得把 `verified` 理解为对任意自然语言理解的保证。

正文通道目前只覆盖有限的明确标签格式；原有专用收费、师资工具保留更具体的业务验证。一般文字回答仍需人工评估其所有附加事实。
